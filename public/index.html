How JobRadar works

1 · DiscoveryEvery 30 minutes the server pulls postings from company-hosted boards (Greenhouse & Lever public APIs) and arbitrary careers pages that embed schema.org JobPosting JSON-LD. These are the same pages recruiters publish to first — boards like LinkedIn/Naukri index them later, so first-seen timestamps here typically beat aggregators by hours to days.
2 · MatchingYour CV is tokenized and matched against each posting: skill-dictionary overlap (55%), skill precision (20%) and text similarity via TF-IDF cosine (25%) → a 0–100 score. Deterministic and explainable — no black box, no API key needed.
3 · SignalsCompetition estimate (from first-seen age + direct-source status), recruiter strictness (density of hard-requirement language), fit sensitivity (how much the score depends on skills vs narrative). These are labeled heuristics to help you prioritize — not insider data.
4 · AlertsNew jobs are checked against your keyword/location/minimum-score preferences; matches are queued as email (Resend) and WhatsApp (Meta Cloud API) digests and flushed every minute.
5 · Apply fastThe companion browser extension autofills application forms from your saved profile — one click per portal. Load it unpacked from the extension/ folder (see README).

Honest limitations

  • Scores and signals are estimates for prioritization — never a prediction of outcomes.
  • Salary data appears only when a source publishes it.
  • "Early" means earlier than job boards, not secret — recruiters see the same page.
  • Single-tenant MVP: no auth. Put it behind a reverse proxy or add auth before exposing publicly.

Extending it

  • Add boards from the Pipeline tab — any Greenhouse/Lever slug, any JSON-LD careers page.
  • Upgrade SQLite → Neon/Supabase Postgres for multi-user (README has the path).
  • Swap the deterministic matcher for an LLM rewrite step (kept out of core so the MVP runs key-free).
